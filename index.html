Challenges & how I solved them

01
One checkout, many vendors

Challenge. A single customer order can contain products from different vendors, but each vendor should only see, fulfil and get paid for its own items.

Solution. Every order item is linked to the vendor company that owns the product, so one order is processed per vendor: each vendor dashboard lists only its own items and statuses, while the customer still tracks a single order.

02
Commissions that stay correct over time

Challenge. Commission and vendor earnings must be exact for every order, and must not change for past orders when a commission rate is updated later.

Solution. Commission is calculated when the order is placed and stored on the order together with the rate that was used, so past orders, balances and reports always match what actually happened.

03
Payouts without double payments

Challenge. Paying a vendor updates several records at once — the orders being paid, the vendor balance and the payout history. A failure halfway could pay an order twice or lose it.

Solution. A payout marks the included orders as paid and creates the payout record inside one database transaction with Prisma, so it either completes fully or not at all — and paid orders are excluded from every later payout.

04
Supplier balances vendors can trust

Challenge. The balance is the first number a vendor checks, and a manually updated total easily drifts out of sync with the real orders.

Solution. Balances are derived from the orders themselves — delivered and not yet paid — with the payout history as an audit trail, so the dashboard always reflects the underlying data.

05
Keeping each vendor's data private

Challenge. Vendors on the same platform must never see each other's orders, customers or revenue — hiding buttons in the interface is not enough.

Solution. Roles and permissions are checked on the server for every protected route and query, and vendor queries are always scoped to the signed-in user's company, using Clerk authentication, Supabase and application-level permissions.
